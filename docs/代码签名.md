# 代码签名（消除"发布者未知 / SmartScreen"提示）

未签名的 exe 第一次运行几乎必然被 SmartScreen 拦一下（蓝色"Windows 已保护你的电脑"）。
彻底解决的办法只有一个：**给 exe 做代码签名**。本文说明本项目的签名接入方式。

## 1. 证书怎么选

| 类型 | 效果 | 成本（2026 年行情，仅参考） |
| --- | --- | --- |
| **EV 代码签名证书** | 签名后**立即**有信誉，基本不再弹窗；私钥在硬件令牌/云 HSM 里 | 约 ¥2000~4000/年，需企业资质 |
| **OV 代码签名证书** | 签名后仍需下载量积累信誉，前期可能仍提示 | 约 ¥600~1500/年 |
| **Azure Trusted Signing** | 微软云签名服务，按量计费；对个人/小团队较友好 | 约 $10/月起，需要身份验证 |
| 自签名证书 | **没用**：别人机器上照样报"不受信任的发布者" | 0 |

> 注意：2023 年 6 月起，主流 CA 要求代码签名私钥存放在硬件令牌或云 HSM 中，
> 不再提供"一个 .pfx 文件随便签"的普通证书（EV 尤其如此）。
> 因此下面的 `-PfxPath` 更适合 **Azure Trusted Signing 导出的签名证书 / 企业内部分发证书**，
> 或者你自建的 CI 签名机（私钥不出内网）。

## 2. 本地打包时签名

```powershell
pwsh -File tools/make-release.ps1 -Version 1.2.0 -Notes "..." `
     -PfxPath "D:\cert\harmoplay.pfx" -PfxPassword "你的口令"
```

脚本会在压缩前对 `口琴谱演奏器.exe` 执行：

```
signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 /f <pfx> /p <密码> <exe>
```

`signtool.exe` 来自 Windows SDK（"Windows SDK Signing Tools"组件）；脚本会自动在
`PATH` 与 `C:\Program Files (x86)\Windows Kits\10\bin\*\x64\signtool.exe` 里找。
找不到时会给出提示并跳过签名（不影响打包）。

## 3. GitHub Actions 自动签名

仓库的 `.github/workflows/release.yml` 已预留签名步骤：

1. 把证书（.pfx，Base64 编码）放进仓库 Secret `SIGN_PFX_BASE64`：
   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("harmoplay.pfx")) | Set-Clipboard
   ```
2. 把口令放进 Secret `SIGN_PFX_PASSWORD`；
3. 推一个 `v*` 标签，工作流会自动：解码证书 → signtool 签名 → 打 zip → 发 Release → 回写 update.json。

没有配置这两个 Secret 时，工作流会**跳过签名**，照常发布（就是现在这样，会弹 SmartScreen 提示）。

## 4. 没有证书时的替代做法

- 在 README / Release 说明里明确写清"未签名 → 点更多信息 → 仍要运行"，并给出校验值（SHA256）；
- 发布包里附 `首次运行说明.txt`（本项目已附）；
- 用户也可以直接自己编译：`dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true`；
  自己编译出来的文件通常不会被 SmartScreen 拦（本地文件带 Mark-of-the-Web 才会触发）。
- 若只是被"下载后带 MOTW"影响：右键 exe → 属性 → 勾「解除锁定」即可。
